# Feature: CV import script

**From build-plan:** feature 19
**Build attempt:** 1
**Branch:** feature/cv-import-script
**Status:** verified

## Goal

`npm run import:cv -- path/to/cv.docx` (or `.pdf`) converts an updated CV into a valid `content/cv.md` draft, so Jonathan can review it with `git diff`, edit it, then commit. No app code changes are needed to update the CV, and nothing is auto-committed.

## In scope

- `scripts/import-cv.mjs`, a plain Node script, wired up as the `import:cv` npm script.
- `.docx` conversion that keeps headings, lists and links, and drops images.
- `.pdf` text extraction, without headings.
- Output that passes the existing `loadKnowledge` validation, with front matter generated by the script.
- A guard so an import never overwrites uncommitted edits to `content/cv.md`.
- Clear errors, a review reminder and a token budget warning.
- The new command in the Commands section of `AGENTS.md`.

## Out of scope

- Portfolio import (feature 20).
- Automatic commits, or any automatic push or deploy.
- AI rewriting of the CV, such as converting it to third person or merging it with the current `cv.md`. Agent's third-person voice comes from `persona.md`.
- Heading inference, column detection or OCR for PDFs.
- Legacy `.doc` files.
- Detecting personal data automatically. The script reminds, and the human decides.
- A test runner, a `--force` flag, or an alternative output path.

## Data / contracts

**Command:** `npm run import:cv -- <path>`. Exactly one path argument, resolved from the current working directory. The extension is matched case-insensitively and must be `.docx` or `.pdf`.

**Output:** always `content/cv.md`, in this form:

```markdown
---
source: CV / Résumé (<DOCX|PDF>, "<input file name without extension>")
last_updated: <YYYY-MM-DD, local date of the import>
role: Primary source. Canonical record of employment, skills and education.
---

<converted body>
```

The `role` line is a constant, carried over from the current file. `persona.md` already gives `cv.md` its priority, so `role` keeps the file consistent with the other knowledge files rather than driving behaviour.

**Test seam:** export `buildCvFile({ body, format, name, date })` as a pure function that takes the date as an argument. Keep the same main guard as `build-knowledge.mjs`, so importing the script has no side effects.

**Check order, each stopping before any write:**

1. Usage: wrong argument count.
2. Unsupported extension.
3. File not found.
4. Guard: `git status --porcelain -- content/cv.md` has output, or git itself fails. An untracked or modified file counts as uncommitted. The message tells Jonathan to commit or discard those edits (`git restore content/cv.md`) first.
5. Conversion throws, covering corrupt or protected files.
6. Empty body after trimming. The message says no text was found and the file may be scanned or image-only.

**Errors:** printed to stderr as `CV import error: <reason>`, matching the `Knowledge base error:` style, with exit code 1. `content/cv.md` is untouched.

**Success output:**

- The path written, and any Mammoth messages.
- For PDFs, a note that headings were not recovered and multi-column layouts may be out of order.
- A reminder to review with `git diff content/cv.md`, to remove anything that should not be public (phone number, home address, salary, right to work), to restore any hand-written detail the import lost, and that `git restore content/cv.md` discards the draft.
- The estimated token count, with a warning over `TOKEN_BUDGET` (6000; the current estimate is 4397).

If `loadKnowledge` throws after the write, for example because of a problem in another content file, print the error in the `Knowledge base error:` style and exit 1. The draft stays in place for review, recoverable with `git restore`.

## Notes for the AI

- All three packages are devDependencies, because nothing in the app imports them. Do not import this script or the converters from `app/` or `lib/`.
- Converter choices, checked against npm metadata on 2026-10-31:
  - `mammoth` 1.13.0 (BSD-2-Clause) with `convertToHtml`, because its README marks markdown output as deprecated and recommends HTML plus a separate converter.
  - `turndown` 7.2.4 (MIT) for HTML to markdown.
  - `pdfjs-dist` 6.4.299 (Apache-2.0) used directly. It requires Node >=22.13 and the local version is 22.17.
  - `unpdf` is rejected because it requires Node >=24. `pdf-parse` is rejected because it pins an older pdf.js and adds a required native canvas dependency.
- Mammoth inlines images as base64 by default. Removing them matters here: one headshot would blow the token budget and could break the free-tier context.
- This script handles local files the owner chose, with no network or server exposure, so it needs no file size limit or sandboxing.
- The real risk is overwriting content. The committed `cv.md` is hand-curated, and importing replaces all of it. That is why the guard exists and why the reminder mentions lost detail.
- The knowledge base is effectively public through the chat, per the plan's data decisions, so the public-content reminder is required, not optional.
- Follow the coding standards: plain `.mjs`, short functions, no em dashes in generated text or comments, and comments only for the why.
