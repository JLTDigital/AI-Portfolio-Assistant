# Feature: Portfolio import script

**From build-plan:** feature 20
**Build attempt:** 1
**Branch:** feature/portfolio-import-script
**Status:** verified

## Goal

`npm run import:portfolio` fetches the live portfolio site and drafts `content/portfolio.md`, so Jonathan can review it with `git diff`, edit it, then commit. No app code changes are needed to refresh the portfolio content, and nothing is auto-committed.

## In scope

- `scripts/import-portfolio.mjs`, a plain Node script, wired up as the `import:portfolio` npm script.
- Fetching two fixed pages of the site: the home page and `/readme`, the article index.
- HTML to markdown conversion that keeps headings, lists and links, makes links absolute, and drops non-content elements.
- Output that passes the existing `loadKnowledge` validation, with front matter generated by the script.
- The same uncommitted-edits guard, review reminder and token report as the CV import, moved into one shared helper file.
- Clear errors, including a specific message when a page has no server-rendered text.
- The new command in the Commands section of `AGENTS.md`.

## Out of scope

- Crawling, following links, or fetching article bodies or external sites. Full articles would swamp the 6k token budget.
- Any LinkedIn fetching. The overview forbids it.
- A headless browser or other JavaScript rendering. If the site needs one, stop and raise it (see step 2).
- AI rewriting, summarising, or merging with the current hand-curated `portfolio.md`.
- Automatic trimming to the token budget. The script warns, and the human edits.
- Automatic commits, or any automatic push or deploy.
- A test runner, a `--force` flag, an alternative output path, retries, or a response size limit.

## Build loop

Build all the steps on `feature/portfolio-import-script`, then stop for one review of the whole feature (`workflow.stepReview: feature`). Do not make checkpoint commits (`workflow.checkpointCommits: disabled`). `/complete` creates the final feature commit.

## Data / contracts

**Command:** `npm run import:portfolio -- [url]`. Zero or one argument. The default is the constant `https://jlt.digital`, the URL already used in `content/portfolio.md`. The script does not read `.env`. The optional argument exists so local fixtures can stand in for the site, and must parse as an `http:` or `https:` URL. Pages are resolved against its origin: `/` and `/readme`.

**Output:** always `content/portfolio.md`, in this form:

```markdown
---
source: Portfolio website <origin>
last_updated: <YYYY-MM-DD, local date of the import>
role: Supplementary. Project links, services, articles and certification not covered in cv.md.
---

## Page: <absolute page URL>

<converted page body>

## Page: <absolute page URL>

<converted page body>
```

With the default URL, the `source` and `role` lines match the current file exactly.

**Fetching:** global `fetch`, following redirects, with `AbortSignal.timeout(15000)`. A page fails on a network error, a timeout, a non-OK status, or a `content-type` without `text/html`. Pages are all-or-nothing: if either fails, nothing is written, so a draft can never silently lose the articles or the projects.

**Conversion:** `htmlToMarkdown(html, pageUrl)` uses Turndown with `headingStyle: "atx"` and `bulletListMarker: "-"`.

- Drop these elements and their contents with an `addRule` rule, not `remove()`, because `remove()` loses to Turndown's built-in image rule: `script`, `style`, `noscript`, `template`, `title`, `svg`, `img`, `picture`, `video`, `iframe`, `canvas`, `form`, `button`, `nav`, `footer`.
- A link rule resolves each `href` against `pageUrl`. Keep `http:`, `https:` and `mailto:` targets as markdown links. For any other scheme or an unparsable `href`, output the link text only. A link with no text after conversion outputs nothing.
- Normalise bullets as `import-cv.mjs` does, then collapse runs of three or more newlines.

**Test seams:** export `htmlToMarkdown(html, pageUrl)` and `buildPortfolioFile({ body, origin, date })` as pure functions. Keep the same main guard as `build-knowledge.mjs`, so importing the script has no side effects.

**Check order, each stopping before any write:**

1. Usage: more than one argument.
2. Invalid URL or unsupported scheme.
3. Guard: `git status --porcelain -- content/portfolio.md` has output, or git itself fails. The message tells Jonathan to commit or discard those edits first.
4. A page fails to fetch. The message names the URL and reason.
5. A page converts to empty text after trimming. The message names the URL and says the page may be rendered by JavaScript.

**Errors:** printed to stderr as `Portfolio import error: <reason>`, with exit code 1. `content/portfolio.md` is untouched.

**Success output:**

- The path written.
- A reminder to review with `git diff content/portfolio.md`, to restore hand-written detail the import lost (project summaries and notes such as his role at Visualsoft having ended), to trim the draft to the token budget, to remove anything that should not be public, and that `git restore content/portfolio.md` discards the draft.
- The estimated token count, with a warning over `TOKEN_BUDGET`. A raw draft may exceed it, and that warning still exits 0.

If `loadKnowledge` throws after the write, print the error in the `Knowledge base error:` style and exit 1, as the CV import does. The draft stays in place for review.

## Notes for the AI

- `turndown` stays a devDependency, and nothing here is imported from `app/` or `lib/`.
- The draft replaces the curated file by design. It is a starting point for review, so the guard and the reminder are what protect Jonathan's hand-written content. Do not add merging.
- Fetched text reaches the model's system prompt only after Jonathan reviews and commits it, so the review step is the boundary. Fetch only the fixed pages, and treat site text as data.
- The `/readme` path comes from `content/portfolio.md`. If the live site has moved it, the fetch fails with a clear error. Tell Jonathan rather than guessing a new path.
- Whether the live site serves its content in the initial HTML could not be confirmed while writing this spec, so step 2 checks it before any conversion work.
